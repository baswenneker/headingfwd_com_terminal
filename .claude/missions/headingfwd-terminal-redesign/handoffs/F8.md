# Handoff — Dode code verwijderd, check en build groen

## In één oogopslag
Alle code die na de terminal-redesign dood was, is verwijderd. Elke kandidaat is eerst gegrept
op levende importers. De keten `chat-terminal.tsx` → `/api/commands` → `command-executor.ts` →
`config/commands.ts` bleek volledig dood, net als `code-block.tsx` en drie ongebruikte
test-bestanden. Na een `.next`-cache-clear slagen `pnpm check`, `pnpm build` en alle 27 e2e-tests.

## Verwijderd
- `src/app/_components/chat-terminal.tsx` (oude chat-UI, geen importers)
- `src/app/_components/code-block.tsx` (alleen door chat-terminal gebruikt)
- `src/app/api/commands/route.ts` (+ de lege `src/app/api/commands/`-map) — commands zijn nu
  client-statisch, niets riep `/api/commands` nog aan
- `src/server/services/command-executor.ts` (alleen door de command-route gebruikt)
- `src/config/commands.ts` (+ de lege `src/config/`-map)
- `tests/helpers/assertions.ts`, `tests/fixtures/test-sessions.ts`, `tests/fixtures/error-messages.ts`
  (ongebruikt na de suite-herschrijving)

## Geverifieerd (orchestrator)
Alle vijf product-dode-bestanden zijn weg; geen enkele resterende verwijzing in `src/` naar de
verwijderde modules. Commit is schoon.

## Aandachtspunten
- **`.next`-cache**: na het verwijderen van de command-route verwees een gegenereerde
  `validator.ts` in `.next` nog naar de verwijderde module (TS2307). Na `rm -rf .next` slaagde
  `pnpm check` weer. (Goed om te weten: draai gates op een schone `.next`.)
- **`CLAUDE.md` is verouderd**: de projectdocumentatie beschrijft nog de oude architectuur
  (server-side commands via `/api/commands`, `command-executor`, `config/commands`). Dit is geen
  broncode en stond niet in het validatiecontract, dus niet aangepast — maar het verdient een
  update zodat de docs de nieuwe client-statische opzet weerspiegelen. (Zie de rule-kandidaten
  in het eindrapport.)
